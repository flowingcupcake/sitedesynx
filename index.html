FAQ

Common questions

Everything you need to know before getting started.

Does Desynx require me to inject into Roblox?
No. Desynx attaches externally to the Roblox process and modifies flags through memory writes — no DLL injection, no kernel drivers. Just run the binary and click Attach.
Will I get banned for using Desynx?
Desynx operates at the FFlag and memory level, not the exploit layer. It does not modify game files or network packets. Risk is minimal compared to traditional executors, but use at your own discretion — no tool can claim zero risk.
The download link isn't working — how do I get the file?
Discord CDN links expire after a period of time. The latest download is always pinned in our #downloads channel on Discord. Join to get the most recent build instantly.
What's the difference between setflag and applyflag?
setflag sets the value in Desynx's internal state and immediately writes it to Roblox memory in one call. applyflag only writes the existing internal value to memory — useful when you've modified the flag table manually and want to push the change without calling setflag again.
Does Desynx work after Roblox updates?
Yes. The v2.0 auto-update system checks for flag definition updates on launch and silently patches them. For binary updates (after major Roblox engine changes) watch #announcements on Discord — we typically push a fix within 24 hours.
Can I use Desynx on multiple Roblox instances?
Multi-instance support is on the v2.1 roadmap. Currently Desynx attaches to the first detected Roblox PID. You can run separate Desynx windows and manually specify the PID via the attach dialog as a workaround.
Desynx Lua API Reference
FFlag Functions 5 functions
desynx.getflag(name)
→ table | nil
Returns a table with flag info: {name, type, typename, value, modified, offset}. Returns nil if the flag is not found.
desynx.setflag(name, value, [type])
→ bool, string?
Sets and applies the flag value in one call. Optional type hint: "Bool", "String", "Int". Returns true on success, false + error message on failure.
desynx.applyflag(name)
→ bool
Writes the existing internal flag value to Roblox memory without changing it. Use after manually modifying the flag table. Returns true on success.
desynx.resetflag(name)
→ bool
Resets the named flag to its original value as read at attach time and writes it back to memory.
desynx.listflags([pattern])
→ string[]
Returns an array of flag names matching the Lua pattern string. An empty or nil pattern returns all available flags.
Desync Functions 2 functions
desynx.setdesync(enabled)
→ bool
Enable or disable desync via NextGenReplicatorEnabledWrite4. Pass true to enable, false to disable.
desynx.getdesync()
→ bool
Returns the current desync state as a boolean.
Utility Functions 5 functions
desynx.isattached()
→ bool, number?
Returns: attached (bool), pid (number, only present when attached).
desynx.notify(msg, [duration], [isError], [isSuccess])
→ void
Shows a notification toast. Duration defaults to 3 seconds. Pass isError=true for red styling, isSuccess=true for green.
desynx.sleep(ms)
→ void
Non-blocking sleep (max 30,000ms). The UI remains responsive during the wait.
desynx.clear()
→ void
Clears the output console panel.
print(...)
→ void
Standard Lua print — all arguments are serialised and output to the console.

Example Scripts 3 examples 
-- Toggle blur off
desynx.setflag("FIntRobloxGuiBlurIntensity", 0, "Int")
desynx.notify("Blur disabled", 2, false, true)

-- Enable desync
desynx.setdesync(true)
local state = desynx.getdesync()
print("Desync active: " .. tostring(state))

-- List all flags matching "Blur"
local flags = desynx.listflags("Blur")
for _, name in ipairs(flags) do
  print(name)
end
